# BrowserWing + Playbot 核心需求文档

本文档定义 BrowserWing 测试平台化方向的核心需求。后续开发以本文档作为产品边界和验收依据。

## 一、产品定位

BrowserWing 从通用浏览器自动化工具，演进为面向 Web 业务系统的智能测试平台。

核心目标是让用户通过少量主流程录制和自然语言描述，快速生成、维护、执行和追踪自动化测试用例。

平台由三部分协同：

- BrowserWing：负责真实浏览器控制、页面语义快照抽取、操作录制和脚本执行。
- Playbot：负责基于页面语义、主流程轨迹和用户意图生成或修改测试用例。
- 测试管理平台：负责项目、版本、页面、用例、执行记录、用户权限和审计。

## 二、核心原则

### 1. 测试用例是核心资产

测试用例不是一次性脚本，而是可查看、可编辑、可执行、可版本化、可回滚的业务资产。

每个测试用例至少包含：

- 标题和业务描述。
- 结构化 Blueprint。
- 可执行脚本内容。
- 当前状态。
- 生成来源。
- 修改记录。
- 执行记录和报告。

### 2. Blueprint 是事实来源

平台优先维护结构化 Blueprint，脚本是由 Blueprint 编译或生成出来的执行产物。

这样做的原因：

- 自然语言修改更容易落到结构化步骤。
- 用例 diff 更清楚。
- 不同执行引擎可以复用同一份测试意图。
- 避免 LLM 直接生成大段脚本后难以维护。

### 3. 页面快照必须是语义快照

BrowserWing 抽取页面时，不能只保存原始 DOM 或普通 selector 列表。页面快照需要面向测试定位和 LLM 理解。

语义快照至少包含：

- URL、标题、页面状态。
- 可交互元素列表。
- 元素 role、tag、text、label、placeholder、aria 属性。
- 可见性、禁用状态、层级路径。
- 父容器、附近文本、表单区域、列表区域等上下文。
- 录制时捕获的 selector、XPath 或稳定路径。
- 必要时包含局部 DOM 片段和截图区域。

### 4. 主流程录制是生成用例的基准

每个业务页面应至少有一条用户亲自录制的正向主流程。Playbot 基于主流程发散生成正向、异常、边界和回归用例。

主流程录制需要保存：

- 用户动作轨迹。
- 每一步目标元素信息。
- 每一步前后的关键页面状态。
- 录制时的语义快照。
- 用户输入值和断言候选。

### 5. 用户可以用自然语言，也可以手动编辑

用户维护用例有两种方式：

- 自然语言让 Playbot 修改用例。
- 直接手动编辑 Blueprint 或脚本。

两种方式都需要留下修改记录，并能区分修改来源。

### 6. 多用户必须有数据隔离

登录认证不是多用户支持的全部。项目、版本、页面、用例、执行记录、LLM 配置、API Key 等数据必须绑定用户或租户边界。

任何列表、读取、修改、删除和执行操作都必须经过数据归属校验。

## 三、目标用户

### 测试人员

测试人员负责维护业务测试用例。

他们需要：

- 录制主流程。
- 查看 AI 生成的用例。
- 调整用例步骤和断言。
- 执行用例并查看报告。
- 对失败用例进行修复或重新生成。

### 开发人员

开发人员关注回归测试、接口变更影响和失败定位。

他们需要：

- 快速理解失败步骤。
- 查看截图、日志、页面快照。
- 对用例脚本进行手动修正。
- 在版本切换后复用已有用例。

### 项目管理员

项目管理员负责项目、用户和权限。

他们需要：

- 管理项目和版本。
- 管理成员和权限。
- 查看执行趋势和覆盖情况。
- 配置 LLM 和执行环境。

## 四、核心业务对象

### Project

项目是测试资产的顶层组织单位。

关键字段：

- 名称。
- 描述。
- 所属用户或租户。
- 创建人。
- 版本列表。

### ProjectVersion

项目版本用于隔离不同业务版本下的页面、录制和用例。

关键字段：

- 项目 ID。
- 版本名称。
- Base URL。
- 描述。
- 状态。

### TestPage

测试页面代表一个业务页面、功能模块或流程入口。

关键字段：

- 版本 ID。
- 页面名称。
- 路由路径。
- 描述。
- 主流程录制。
- 测试用例列表。

### PageScript

页面录制脚本保存主流程轨迹和页面快照，是 Playbot 生成用例的输入。

关键字段：

- 页面 ID。
- 名称。
- ActionTrace。
- DOMSnapshot 或 SemanticSnapshot。
- 录制元数据。

### TestCase

测试用例是真正被维护和执行的测试资产。

关键字段：

- 页面 ID。
- 标题。
- 描述。
- Blueprint。
- ScriptContent。
- 状态。
- 来源。
- 修改记录。
- 执行记录。

### LLMRefinement

记录用户通过自然语言对用例进行的二次修改。

关键字段：

- 用例 ID。
- 用户输入。
- 修改前 Blueprint。
- 修改后 Blueprint。
- 是否已应用。
- 创建人和创建时间。

### TestExecution

记录单次执行结果。

关键字段：

- 用例 ID。
- 状态。
- 错误信息。
- 耗时。
- 报告数据。
- 截图、视频、日志、页面快照。

## 五、核心流程

### 1. 创建项目和版本

用户创建项目，填写项目名称、描述和默认 Base URL。系统自动创建默认版本。

验收标准：

- 用户能看到自己有权限的项目。
- 项目下至少有一个默认版本。
- 版本可以复制，复制后页面、主流程和测试用例一起复制。

### 2. 创建业务页面

用户在项目版本下创建业务页面，填写页面名称、路径和描述。

验收标准：

- 页面归属于指定项目版本。
- 页面可以展示主流程是否已录制。
- 页面可以展示已生成测试用例数量和最近执行状态。

### 3. 录制主流程

用户进入 BrowserWing 浏览器录制页面，完成一条正向业务流程。系统保存 ActionTrace 和语义快照。

验收标准：

- 录制完成后回到对应 TestPage。
- TestPage 显示主流程已就绪。
- 主流程数据可被 Playbot 读取。
- 重新录制会生成新的主流程版本或明确替换旧主流程。

### 4. Playbot 生成测试用例

用户点击智能生成。系统将 Base URL、页面路径、主流程轨迹和语义快照传给 Playbot。Playbot 返回结构化测试用例 Blueprint。

验收标准：

- 生成过程有明确 loading 和错误提示。
- 生成结果保存为 TestCase。
- 每个用例至少包含标题、描述、步骤和断言。
- 用例可覆盖正向、异常、边界和回归场景。
- Playbot 不应凭空生成无法定位的元素。

### 5. 查看和编辑测试用例

用户进入用例详情页，查看 Blueprint、脚本、生成来源和历史执行结果。

验收标准：

- 用户可以查看结构化步骤。
- 用户可以查看或编辑生成脚本。
- 用户可以保存手动修改。
- 修改后记录修改人、修改来源和修改时间。

### 6. 自然语言修改用例

用户输入自然语言，例如“增加密码为空的校验”或“把断言改成检查错误提示”。Playbot 基于当前 Blueprint 生成修改建议。

验收标准：

- 修改前后 Blueprint 可比较。
- 用户可以选择应用或放弃。
- 应用后产生 LLMRefinement 记录。
- 修改失败时不覆盖原用例。

### 7. 执行测试用例

用户可以执行单个用例、页面下全部用例、版本下全部用例。

验收标准：

- 执行结果保存为 TestExecution。
- 报告包含状态、耗时、错误信息和关键日志。
- 失败用例能定位到失败步骤。
- 必要时保存截图或页面快照。

### 8. 失败修复闭环

用户可以基于失败报告让 Playbot 分析失败原因并提出修复建议。

验收标准：

- Playbot 可读取失败步骤、错误信息和当前语义快照。
- 修复建议不自动覆盖用例，必须由用户确认。
- 修复记录进入 LLMRefinement。

## 六、功能需求

### 项目和版本管理

- 创建、查询、更新、删除项目。
- 创建、更新、删除、克隆版本。
- 版本克隆时复制页面、主流程和测试用例。
- 项目和版本必须受权限控制。

### 页面管理

- 创建、查询、删除业务页面。
- 保存或替换主流程录制。
- 展示主流程状态。
- 展示用例数量和最近执行状态。

### 页面语义快照

- 支持通过 BrowserWing Executor 获取页面快照。
- 支持保存快照到 PageScript。
- 支持抽取稳定元素线索。
- 支持给 Playbot 提供结构化输入。

### 用例生成

- 支持对单个页面生成测试用例。
- 支持重新生成并选择覆盖、追加或保留旧用例。
- 支持生成进度和错误展示。
- 支持保存 Playbot 返回的 Blueprint。

### 用例编辑

- 支持用例详情页。
- 支持 Blueprint 可视化编辑。
- 支持脚本文本编辑。
- 支持自然语言修改。
- 支持修改历史查看。

### 用例执行

- 支持单个用例执行。
- 支持批量执行。
- 支持执行结果持久化。
- 支持失败报告展示。

### 多用户和权限

- 用户只能访问有权限的项目。
- 项目数据必须绑定用户或租户。
- API Key 必须绑定用户。
- 管理员可管理用户和权限。

## 七、非功能需求

### 可靠性

- 用例生成失败不得破坏已有用例。
- 用例执行失败必须保存可诊断信息。
- 录制替换需要有明确提示或历史记录。

### 可维护性

- Playbot 返回结构必须稳定。
- Blueprint schema 需要版本号。
- API 契约需要前后端一致。
- 不引入第二套事实来源。

### 可观测性

- 生成、修改、执行都需要记录日志。
- 关键错误需要带 trace id。
- LLM 调用需要记录模型、耗时和错误。

### 安全性

- 不在数据库或日志中明文保存 LLM API Key。
- 脚本执行需要限制用户数据访问范围。
- 多用户数据必须隔离。

## 八、当前代码基础

现有代码已经具备以下基础：

- 项目、版本、页面、录制、用例、调优、执行模型：`backend/models/testing.go`。
- 项目和页面基础 API：`backend/api/project_handlers.go`。
- BrowserWing Executor 页面快照和元素操作 API：`backend/api/router.go`。
- Playbot Go 调 Python CLI 服务：`backend/services/playbot/service.go`。
- Playbot 测试用例生成 Agent：`playbot-engine/app/agents/test_case_agent_v2.py`。
- 前端业务页面管理入口：`frontend/src/pages/TestPageManager.tsx`。

主要缺口：

- 缺少生成测试用例 API。
- 缺少 TestCase 的 CRUD API。
- 缺少用例详情、编辑、自然语言修改页面。
- 缺少用例执行和报告闭环。
- 多用户数据模型缺少项目归属字段。
- Playbot Python 路径和虚拟环境调用需要配置化。

## 九、首个可交付版本范围

首个可交付版本优先完成一条完整闭环：

```text
项目版本 -> 业务页面 -> 录制主流程 -> 生成测试用例 -> 查看用例 -> 执行用例 -> 查看结果
```

首版可以暂缓：

- 团队级复杂权限。
- 大规模并发执行。
- 高级统计看板。
- 用例市场。
- CI/CD 深度集成。

首版必须完成：

- 生成用例 API。
- 保存 TestCase。
- 用例详情页。
- 单用例执行。
- 执行结果保存。
- 基础数据隔离设计。
